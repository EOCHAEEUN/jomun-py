# 온라인 질의 파이프라인 슬라이드 교체 문안

첨부한 **4. ONLINE QUERY PIPELINE** 화면의 두 열을 아래 문구로 교체한다. 표기명은 **BM25**다.

## 슬라이드에 넣을 문구

**제목:** 온라인 질의 파이프라인

**한 줄 요약:** 법률 질문은 원문 검색, 선택적 서비스 설명은 규칙 사전 점검으로 연결

| ① 법률 질문 경로 (`/ask`) | ② 서비스 맥락 경로 (`/ask` 서비스 모드) |
| --- | --- |
| 01. Dense + Sparse(IDF) 검색 — 의미와 법률 용어를 함께 찾음 | 01. 서비스 사실 추출 — 목적·대상·판단 방식 파악 |
| 02. RRF 결합 — 두 검색의 **순위**를 합쳐 후보 선정 | 02. Rule Engine 사전 점검 — 서비스 적용 조건 확인 |
| 03. 다중 질의·규칙 재정렬 — 관련 조문 우선 | 03. 미확정 조건 유지 — “추가 확인”으로 표시 |

**하단 결합 문구:** 검색한 원문과 서비스 점검 결과를 LLM에 전달해 근거가 붙은 답변을 생성합니다.

**BM25 보조 문구:** “별도 `/api/build` 서비스 점검 기능은 BM25로 조문 후보를 검색합니다. 이 슬라이드의 `/ask` 서비스 모드는 Qdrant 검색과 Rule Engine 점검을 사용합니다.”

## 발표자 메모 (약 25초)

“법률 질문은 Qdrant의 의미 검색과 어휘 검색을 RRF로 합친 다음 관련 조문을 재정렬합니다. 서비스 설명이 있으면 사실을 추출하고 Rule Engine으로 조건을 사전 점검해 같은 답변에 붙입니다. 별도 `/api/build`에서는 BM25로 조문 후보를 검색하지만, 이 온라인 QA 경로에는 BM25를 쓰지 않습니다.”

## 수치가 필요한 다음 슬라이드용

| 실험 | 기존 | BM25 | 해석 |
| --- | ---: | ---: | --- |
| 서비스 점검 후보 재현율, dev 11건 | Chroma 0.89 | **0.94** | dev 결과로 BM25 채택 |
| 서비스 점검 후보 재현율, held-out v1 11건 | Chroma 0.87 | **0.93** | 평균 후보 27.2개 → 28.6개 |
| 서비스 점검 최종 판정, held-out v1 | 22/36 (0.61) | **25/36 (0.69)** | 검색 누락 3건 개선, 특성·규칙 오류 11건 잔존 |

QA용 395개 청크·개발 질문 12개에서는 **현행 sparse(IDF) Hit@3 1.000**, 단어 기반 정식 BM25 **0.583**, 단어+글자 bigram BM25 **0.917**이었다. 따라서 QA 온라인 검색을 BM25로 교체했다고 말하면 안 된다. 이 수치는 개발 질문 결과이며 답변 정확도나 신규 질문 성능이 아니다. 서비스 점검의 BM25 결과와 평가셋도 다르다.
